# Round 1 - Agent A: 反代优化方案提案

## 概述
基于对 clewdr 项目的深入代码分析，识别出 7 大类可能暴露代理特征的薄弱环节。

---

## 方案 1：HTTP 指纹伪装

### 问题描述
| 特征 | 当前实现 | 风险等级 | 代码位置 |
|-----|--------|--------|--------|
| User-Agent 硬编码 | `chrome-code/2.1.76` 仅用于 Claude Code 路径 | 高 | `constants.rs:22` |
| Web 版本无 UA | Web 端完全依赖 `Emulation::Chrome136` | 高 | `claude_web_state/mod.rs:131` |
| Header 顺序固定 | 手动添加 ORIGIN→COOKIE→REFERER→ACCEPT | 中 | `build_request()` |
| Accept 头硬编码 | `"text/event-stream"` 仅在发送聊天时 | 中 | `claude_web_state/chat.rs:178` |
| TLS 指纹 | 使用标准 wreq 库, 无随机化 | 中 | 依赖 wreq 6.0.0-rc.28 |

### 解决方案
- **方案 1.1**：动态 User-Agent 管理系统（维护 Web/Code 两套 UA 列表，轮换使用）
- **方案 1.2**：HTTP Header 顺序随机化（多种预设顺序模拟不同浏览器行为）
- **方案 1.3**：TLS 指纹多样化（动态选择 TLS 配置，支持 Session Resumption 等特性）

### 实现难度：中等（2-3 天）

## 方案 2：请求行为模式

### 问题描述
| 特征 | 当前实现 | 风险 | 代码位置 |
|-----|--------|------|--------|
| 重试无延迟 | 立即重试，无随机延迟 | 高 | `claude_web_state/chat.rs:39-76` |
| 并发模式固定 | 每个请求顺序执行 | 中 | 顺序 async 调用 |
| Cookie 轮换无规律 | 按 FIFO 队列分配 | 高 | `cookie_actor.rs:49` VecDeque |
| 对话清理同步 | 请求完成后立即删除对话 | 中 | `clean_chat()` 同步调用 |

### 解决方案
- **方案 2.1**：人类行为延迟模拟（指数退避 + 随机抖动 + 反应时间模拟）
- **方案 2.2**：Cookie 轮换策略优化（Random / RoundRobinWithSkips / WeightedByAge 多策略）
- **方案 2.3**：请求时间戳抖动（秒级舍入 + 网络浮动模拟）

### 实现难度：中等（2 天）

---

## 方案 3：Cookie/Session 管理

### 问题描述
| 特征 | 当前实现 | 风险 | 代码位置 |
|-----|--------|------|--------|
| Cookie 池管理过度 | VecDeque 保存所有 Cookie | 超高 | `cookie_actor.rs:49-52` |
| Cookie 复用周期固定 | 5h session / 7d 周期窗口 | 高 | `cookie_actor.rs:17-18` |
| Session 存储不隔离 | 全局共享 Client cookie_store | 中 | `SUPER_CLIENT.to_owned()` |
| Token 过期检查显式 | 请求前检查过期时间 | 中 | `check_token()` |

### 解决方案
- **方案 3.1**：Cookie 生命周期伪装（fake_first_use_time，模拟为老 Cookie）
- **方案 3.2**：Session 隔离和复用模拟（per-session cookie_store）
- **方案 3.3**：Token 过期检查规避（概率化过期报告）

### 实现难度：困难（3-4 天）

---

## 方案 4：WebSocket/SSE 行为

### 问题描述
| 特征 | 当前实现 | 风险 |
|-----|--------|------|
| SSE 流处理无加工 | 直接透传事件流 | 中 |
| 流分块无延迟 | 连续发送 chunks | 中 |
| 保活信号不规则 | Axum SSE 默认配置 | 低 |

### 解决方案
- **方案 4.1**：流数据传输延迟模拟（基于内容长度的"阅读时间"）
- **方案 4.2**：流完整性检查规避（事件序列跟踪验证）

### 实现难度：中等（1.5 天）

---

## 方案 5：网络层特征

### 问题描述
| 特征 | 当前实现 | 风险 |
|-----|--------|------|
| IP 地址轮换无规律 | 通过单一 Proxy | 高 |
| DNS 解析直通 | 依赖操作系统 DNS | 中 |
| 代理链特征 | Proxy 头泄漏 | 中 |

### 解决方案
- **方案 5.1**：代理池管理（ProxyPoolConfig + ProxyManager，支持多代理轮换）
- **方案 5.2**：DNS 泄漏规避（DNS over HTTPS）
- **方案 5.3**：代理链特征隐藏（清理 Via/X-Forwarded-* 头）

### 实现难度：困难（3-5 天）

---

## 方案 6：请求内容特征

### 问题描述
| 特征 | 当前实现 | 风险 |
|-----|--------|------|
| Content-Type 固定 | 总是 application/json | 中 |
| Accept 头不多样化 | 仅 text/event-stream | 中 |
| 自定义头缺失 | 缺少浏览器自定义头 | 中 |

### 解决方案
- **方案 6.1**：Content-Type 和 Accept 头多样化
- **方案 6.2**：浏览器扩展特征模拟（Sec-* 头、扩展标识）
- **方案 6.3**：请求体字段顺序随机化

### 实现难度：中等（1.5 天）

---

## 方案 7：错误处理行为

### 问题描述
| 特征 | 当前实现 | 风险 |
|-----|--------|------|
| 错误重试模式固定 | 无延迟立即重试 | 中 |
| 断路器缺失 | 无断路器，一直重试 | 中 |
| 失败后清理 | 所有失败都删除对话 | 低 |

### 解决方案
- **方案 7.1**：人类化错误重试（概率化放弃 + 智能决策）
- **方案 7.2**：错误断路器（Closed/Open/HalfOpen 三状态）
- **方案 7.3**：错误响应延迟规避

### 实现难度：中等（1.5 天）

- **第二阶段（2-3 周）**：SSE 优化 + 错误处理 + 内容特征
- **第三阶段（3-4 周）**：网络层特征
